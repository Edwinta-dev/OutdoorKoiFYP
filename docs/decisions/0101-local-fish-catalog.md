Status: implemented · Issue: #101 · Date: 2026-10-19

## In short

The local Supabase development seed now loads the repository's fish characteristics CSV into `Fish_Database`. Re-running the seed replaces only catalog entries with titles supplied by that CSV, so onboarding has species data without adding reference rows to a migration.

## How it works

1. The local development seed reads the demo pond as before.
2. When the Supabase profile writes its local database seed, it reads the fish characteristics CSV shipped in `AquariumScraper`.
3. In the same database transaction, existing rows whose titles occur in that CSV are removed, then all CSV rows are inserted into `Fish_Database` with their header names mapped directly to the table's quoted columns.
4. The memory profile continues to use only its demo pond seed; it does not load the catalog into its narrower storage adapter.

## Main design choice

Load the CSV at the local database boundary instead of introducing a migration or adding it to the general demo seed. This keeps reference data out of schema history and avoids passing an unsupported table through `MemoryStorage`. A migration would be better if every database environment, including deployed environments, must own the species reference data.

## Traps: why the obvious fix is wrong

- Adding `Fish_Database` to the ordinary demo seed sends it through `MemoryStorage`, whose table allowlist intentionally models service data rather than every Supabase table.
- Appending rows without deleting the matching titles makes repeated local seeding fail on the table's primary key.
- Deleting the entire table would erase local additions unrelated to the repository CSV.

## Components

- `Backend/koi/dev/seed.py::load_fish_catalog` — CSV reader
- `Backend/koi/dev/local_db.py::seed` — adds catalog rows to local seed transaction
- `Backend/koi/dev/local_db.py::_delete` — replaces matching catalog titles

## Breaks or needs follow-up

None.

## Problem and constraints

The local species lookup table had no reference rows. The requested source is `AquariumScraper/fish_characteristics_open_media.csv`; this issue requests local dev seeding rather than a schema migration.

## Alternatives considered

- Add a migration containing reference data — not chosen because the issue explicitly assigns the data to the local dev seed.
- Put the catalog in the shared demo JSON — not chosen because that data is loaded by the memory profile too.

## Trade-offs

The catalog is available only in the local Supabase profile. Deployments remain responsible for their own species reference rows.

## Key parameters

None.

## Assumptions

The CSV header matches the quoted `Fish_Database` columns and `Title` remains the primary key.

## Edge cases

- Handled: repeated seed runs replace rows with matching titles.
- Not handled: rows removed from the source CSV are not automatically deleted from the database.

## Not verified

The local Supabase integration could not be run in this environment.

## To change this

To distribute the catalog to deployed environments, add a separately reviewed migration or deployment data load; the local seed currently owns its local population.

## Rollback

Remove catalog loading from `Backend/koi/dev/local_db.py::seed` and its CSV helper. Existing local rows may remain until manually removed or the local database is reset.
