Status: implemented · Issue: #115 · Date: 2026-10-19

## In short
The Algal Growth Outlook card no longer displays a camera thumbnail. Its forecast headline, coverage, growth, frame count and grounding details remain in the card.

## How it works
1. The detail screen continues to load the algae forecast and gives it to the outlook card.
2. The card starts with its title and urgency pill.
3. It presents the forecast headline directly below the title, followed by the existing coverage meter and forecast metrics.
4. The remaining provenance and threshold text still explains the camera history and how the threshold is set.

## Main design choice
The card removes its thumbnail and displays the headline at full available width. The other plausible option was to repair the URL using the app's Supabase client, as the rating card does. The issue records the owner's choice to remove the duplicate photo; URL repair would preserve the unwanted duplication and add another image-loading path. URL reconstruction would be preferable if the outlook later needs to show this image for a distinct task.

## Traps: why the obvious fix is wrong
- Hiding only the image while retaining its old fixed-size slot would waste space and keep the headline constrained. The headline now uses the card's full width.
- The forecast model still supplies `latest_image_url` because the rating flow consumes image data. Removing that API value is outside this UI issue and could affect the rating card.

## Components
- `MobileUI/mobile_app/lib/widgets/detail_graph/algae_status_card.dart::AlgaeStatusCard` - forecast presentation
- `MobileUI/mobile_app/lib/widgets/detail_graph/algae_status_card.dart::_forecastCard` - full-width headline
- `MobileUI/mobile_app/lib/widgets/detail_graph/algae_status_card.dart::_cameraThumbnail` - removed

## Breaks or needs follow-up
None. The card's duplicate image presentation was intentionally removed.

## Problem and constraints
The image duplicated the rating card's photo and used the twin's camera URL directly. The issue scopes the change to the mobile algae status card; the forecast data contract and rating card remain untouched.

## Alternatives considered
- Rebuild the URL with the Supabase client - not chosen because the owner asked to remove the duplicate image.
- Leave a placeholder - not chosen because no image slot is needed once the photo is removed.

## Trade-offs
Users no longer see a camera frame in this outlook card. The card has more room for its headline, and its other forecast details remain visible.

## Key parameters
None.

## Assumptions
The rating card below remains the place to inspect the latest photo. If that card is removed or hidden in a future layout, this card will still have no image.

## Edge cases
- Handled: a missing, inaccessible or malformed forecast image URL cannot create a failed image widget in this card because it no longer builds one.
- Not handled: none identified.

## Not verified
The phone layout was not manually inspected on a Galaxy A32. No detail-card golden exists in the current golden suite.

## Changes outside the scope
This required decision record is outside the issue's source-file scope.

## How it was verified
See the issue result block for commands actually run.

## To change this
To show a distinct forecast image in the future, restore a thumbnail in `MobileUI/mobile_app/lib/widgets/detail_graph/algae_status_card.dart::_forecastCard` and resolve its URL through the app's storage client; the cost is an extra image-loading state and potential duplicate content.

## Rollback
Revert the card layout and thumbnail removal together. Check that the latest-image URL is reachable in the target phone network and that the rating card does not make the duplicate redundant again.
