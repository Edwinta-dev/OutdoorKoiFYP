Status: implemented · Issue: #106 · Date: 2026-10-19

## In short

An empty Today feed now reports that weather rules could not be checked and names PREEMPT and WINDOW. If every returned action has instead been dismissed, the feed says so and gives the existing count, rather than implying that the rules were unassessed.

## How it works

1. The dashboard supplies the Today feed with actions that fired, or null when the dashboard did not load.
2. The feed removes actions dismissed for the current day. If that leaves an empty list because actions were dismissed, it reports that count; if the original list was empty, it says weather rules could not be checked and names PREEMPT and WINDOW.
3. When actions remain, the feed continues to show them. When the dashboard did not load, its existing unavailable message remains in place.

## Main design choice

The widget scope has no per-rule status input. A separate `/actions` fetch or dashboard contract change would require code beyond the issue scope. PREEMPT and WINDOW are currently returned as `insufficient_data` when their inputs are unavailable (`Backend/koi/models/ladder.py::preempt`, `::window`); this UI change names those known unchecked rules. Passing live per-rule statuses would be better once they are present in the dashboard payload, because REACT and NOWCAST can also be unassessed depending on retained inputs.

## Traps: why the obvious fix is wrong

Do not restore “The pond needs nothing today”: an empty `next_actions` list does not distinguish quiet assessed rules from rules lacking data. Do not use the unassessed message after the owner dismisses every action; the original list length distinguishes that case.

## Breaks or needs follow-up

## Problem and constraints

The widget receives fired actions only. It cannot accurately infer REACT and NOWCAST status from that list.

## Alternatives considered

- Add a second `/actions` request — expands scope and adds a request.
- Add per-rule statuses to the dashboard — requires backend and client contract work beyond this issue.

## Trade-offs

The message names the two currently known unassessed rules, but does not enumerate data-dependent REACT or NOWCAST failures because the widget receives no statuses.

- Not handled: data-dependent status of REACT and NOWCAST is unavailable to this widget.
