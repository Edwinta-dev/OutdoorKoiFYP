# 0026: Lead-time action ladder in the digital twin
Status: partial · Issue: #26 · Date: 2026-10-09

## In short

The API now exposes the four weather rules at `/v1/ponds/{pond}/actions` and in the dashboard response. Valid quiet weather is distinct from an input window that cannot be assessed. REACT and NOWCAST can use the retained runtime data; PREEMPT and WINDOW await runtime series that match the validation definitions.

## Problem and constraints

The validation evidence was calculated on network-mean daily temperatures and a pooled set of 24-hour forecast periods. The runtime history described by #24 is retained per assigned station or region. The issue amendment also requires that decisions use only data available at decision time, that rainfall coverage be checked, and that missing data never imply a healthy result. The change is limited to the action ladder, its API integration, and supporting tests and documentation.

## Approach

`Backend/koi/models/ladder.py::react` checks the complete previous Asia/Singapore calendar day at the assigned rainfall station and fires at 50 mm. `::nowcast` evaluates only a retained 2-hour issuance available and valid now. Both `::preempt` and `::window` return explicit `insufficient_data` when their matched inputs are unavailable. The shared helper `Backend/koi/api/routes.py::_lead_time_actions` is called by the actions route and dashboard builder, preventing the two responses from diverging.

`Backend/tools/regenerate_ladder_params.py` calculates the observed hot threshold, outlook threshold and pooled rank cutoff from committed training rows through 2024-12-31. The daily labels export contains pooled rank values; its 16th percentile is rank 0.10 because rank values have ties. The committed held-out WINDOW precision recalculates to 104 dry days among 121 valid firing days, or 0.8595. The daily labels export does not include PREEMPT's future three-day heat outcome. Its test therefore checks the notebook's committed validation record, 0.8851 over 87 calls, rather than recalculating the unavailable target.

## Alternatives considered

| Option | Why not chosen |
|---|---|
| Use the latest cached forecast to reconstruct an earlier action | It would use hindsight and violate the as-of rule. |
| Apply pooled thresholds directly to one assigned station | The validation does not establish that these series have equivalent distributions. |
| Treat missing inputs as no action | That would make unavailable weather look safe. |

## Trade-offs

The data-state distinction avoids false assurance, while the runtime dashboard currently cannot fire PREEMPT or WINDOW. That changes only when #24 retains matched daily network and pooled forecast inputs or equivalent assigned-series evidence is validated.

## Assumptions

REACT uses the assigned rainfall station's interval coverage as the best available local measure. Its previous-day window is the Singapore local day. If that station is not representative of the pond, the rule may miss localized rain.

## Edge cases

Incomplete rainfall, absent nowcast, and unavailable PREEMPT/WINDOW inputs produce `insufficient_data`. Complete rain below 50 mm and a valid non-rain nowcast are assessed with no action. Forecasts issued after the decision time are not selected.

## Changes outside the scope

The API response type, OpenAPI description, model tests, API tests, model documentation and this decision record support the requested route and dashboard field. No schema, storage adapter or camera contract changed.

## How it was verified

The focused ladder suite passed 7 tests and 18 assertions. The WINDOW test recalculates precision from `NEA_Data_Analysis/exploration_outputs/daily_labels.csv`; the PREEMPT test checks the matching held-out aggregate in `intervention_validation.csv`. The existing prior full-check run reported inaccessible pytest temporary paths; the current full-check result is recorded in the issue result block.

## To change this

Thresholds and evidence summaries are regenerated by `Backend/tools/regenerate_ladder_params.py`. Runtime selection is in `Backend/koi/api/routes.py::_lead_time_actions`; it must keep using retained as-of history. PREEMPT/WINDOW need a validated matching series before their actions can be enabled.

## Rollback

Remove the actions route, dashboard action population, ladder parameters and model functions together. No migration or stored row depends on these additions.
