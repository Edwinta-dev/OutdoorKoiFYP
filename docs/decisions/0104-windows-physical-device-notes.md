## In short

`docs/dev.md` now records the Windows-specific setup issues encountered when running the local Supabase profile against a physical Android phone. It covers the reserved Supabase port range, TLS-scanning antivirus, SDK account permissions, and same-Wi-Fi requirement.

## How it works

1. Start the local Supabase profile and configure the app with the development machine's LAN address, following the existing setup section.
2. Put the phone and development machine on the same Wi-Fi. The phone uses that LAN address to reach both the twin API and Supabase REST service; the seeded camera links also need the host-reachable Supabase URL.
3. If Windows reports ports 54289-54388 unavailable, first restart WinNAT in an Administrator PowerShell, then stop and start the local Supabase stack from the repository. These are the steps recorded for the Hyper-V/WSL reservation seen during the device session.
4. If TLS-scanning antivirus software breaks Gradle downloads, set the specified `JAVA_TOOL_OPTIONS` value in the shell that launches Flutter or Gradle and retry. Java then validates TLS with the Windows root certificate store.
5. Keep the Android SDK under the Windows account that runs the build. This avoids the observed `javac AccessDenied` failure that occurred despite the other account's SDK being readable.

## Main design choice

The notes are placed beside the existing physical-device Supabase image URL guidance in `docs/dev.md`, where a developer needs them during setup. A separate Windows guide would duplicate the network and local-stack context. These are documented as fixes observed on the 2026-10-11 Galaxy A32 debug session; other causes of similar errors may need different fixes.

## Traps: why the obvious fix is wrong

- Read access to another Windows user's SDK is not sufficient: the observed build still failed with `javac AccessDenied`.
- Restarting Supabase alone did not address the observed port reservation; the recorded sequence restarts WinNAT first.

## Key parameters

- Ports `54289-54388` — range stated in issue #104; the reported reservation prevented the Supabase stack from starting.
- `JAVA_TOOL_OPTIONS=-Djavax.net.ssl.trustStoreType=Windows-ROOT` — value stated in issue #104 for Java TLS validation through the Windows root store.

## Assumptions

The reader is using the local Supabase profile and has permission to restart WinNAT as an administrator. Without administrator access, the recorded port recovery step cannot be performed.

## Edge cases

- Not handled: other reasons for occupied ports, denied SDK access, or failed Gradle downloads.
